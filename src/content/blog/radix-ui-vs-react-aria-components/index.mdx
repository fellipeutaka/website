## Introduction

Radix Primitives and React Aria Components provide unstyled, accessible building blocks for React applications. Both handle interaction details such as keyboard navigation and screen reader support while leaving visual design to you.

This comparison focuses on Radix Primitives and the `react-aria-components` package. Radix Themes and React Spectrum are separate libraries and are outside its scope. React Aria hooks are identified explicitly where a component equivalent is unavailable.

_Last reviewed: October 24, 2026. Release labels reflect the documentation on that date._

## Radix UI

Radix Primitives provides composable components for patterns such as dialogs, menus, popovers, and tooltips. Components are split into parts so you can choose their structure and appearance.

The primitives are [unstyled and compatible with different styling solutions](https://www.radix-ui.com/primitives/docs/guides/styling). Radix Themes is a separate styled component library; its components, such as Button, should not be counted as Primitives exports.

The [Primitives catalog](https://www.radix-ui.com/primitives/docs/overview/introduction) also includes preview components. Their availability and release status are listed separately below.

## React Aria Components

React Aria Components covers interaction patterns as well as collections, date and time inputs, color controls, and form fields. Its composable parts let you reuse elements across different patterns.

It [does not include styles by default](https://react-aria.adobe.com/styling). The styled examples in the documentation demonstrate customization; they are not default themes bundled with the component package.

React Aria also exposes a [lower-level hooks API](https://react-aria.adobe.com/hooks). Hooks return behavior and DOM props for your own elements. A hook can help you build an interaction, but it is a different starting point from a composed component.

## Important differences behind the checkmarks

[useContextMenu](https://react-aria.adobe.com/useContextMenu) handles context menu events across input methods. It does not provide the complete menu: positioning, open state, and menu rendering still need to be implemented or composed with other building blocks.

[PreviewTrigger](https://react-aria.adobe.com/PreviewTrigger) opens a non-modal popover on hover, focus, or long press, and allows interactive content. It covers the preview pattern associated with a hover card, but its interaction behavior should be evaluated separately from Radix Hover Card.

[Separator](https://react-aria.adobe.com/Separator) is a component in its own right. React Aria support is no longer limited to the `useSeparator` hook.

[Dialog](https://react-aria.adobe.com/Modal) supports both `dialog` and `alertdialog` roles. React Aria composes modal behavior with Modal and ModalOverlay instead of exporting a separate AlertDialog component.

Disclosure and DisclosureGroup appear under their own names and under the equivalent Collapsible and Accordion patterns. Their Radix equivalents are therefore marked consistently in both places. NavigationTree is a hierarchical navigation pattern; it is listed separately from Navigation Menu.

The release labels for [Autocomplete](https://react-aria.adobe.com/Autocomplete), [NavigationTree](https://react-aria.adobe.com/NavigationTree), [TokenField](https://react-aria.adobe.com/TokenField), and [Toast](https://react-aria.adobe.com/Toast) matter when evaluating production requirements. A checkmark records availability, not a promise that every API has reached a stable release.
